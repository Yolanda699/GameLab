01Overview

TravelTrove is a gamified travel app that turns your trips into a cozy digital home. Exploring real cities earns e-souvenirs to decorate your virtual house, and an AI pet companion plans personalized itineraries, flags safety concerns and connects you with like-minded travelers.

This is a design and research prototype. I used a saved ComfyUI workflow with a style LoRA, reference image, framing controls and fixed sampling settings to develop a consistent souvenir collection, then incorporated the assets into a Figma prototype.

03AI concept-art pipeline

The concept needed a collection of souvenirs that could sit together in the same room. Early text-to-image results varied in palette and line weight, so I fixed the generation settings and changed the subject for each asset.

The stack

ComfyUI

Node-graph runner, so the whole generation is a saved JSON workflow rather than a chat history. The graph is the thing under version control.

SDXL checkpoint

Base model, fixed for the whole set. Keeping the checkpoint fixed made comparisons between runs more useful.

Style LoRA

Trained in kohya_ss on ~40 curated reference frames in the cozy-isometric look I was targeting (Animal Crossing-style: flat warm palette, brown outlines, soft shading). Applied at a fixed weight – see the section below for how it was trained and tuned.

IP-Adapter

A single style reference image on every run, so the LoRA has a second anchor and new subjects are less likely to shift the palette.

ControlNet (depth / lineart)

Feeds a simple silhouette block-in, so each souvenir lands at the same scale, angle and framing instead of a random camera.

Fixed sampling

Same sampler, steps, CFG and seed schedule across the batch. Only the subject token moves.

RMBG + Real-ESRGAN

Background removal to transparent PNG, then upscale, so assets drop straight into the UI as sprites.

Training the style LoRA

I trained a style LoRA to guide the souvenir illustrations toward a shared palette, outline style and shading treatment. I compared settings using subjects outside the training set to check whether the style carried over.

Dataset · ~40 frames

Curated for style, not subject. I deliberately picked frames with different objects – furniture, exteriors, characters, props – so the network had nothing consistent to latch onto except the rendering. Anything with UI, text or a strong recognisable silhouette was cut.

Prep · 1024 buckets

Cropped into SDXL’s resolution buckets so nothing was squashed. Aspect distortion teaches the model the distortion.

Captions · subject descriptions

I captioned the objects in each training image, such as a stool or fern, while leaving recurring style descriptions out. The aim was to associate the visual treatment with the adapter while retaining control over the subject.

Rank · dim 12 / alpha 6

I started with a low rank to limit training capacity, then checked whether new subjects retained the intended style without reproducing training compositions.

Learning rate · 1e-4 UNet, 4e-5 text encoder

I used a lower learning rate for the text encoder and checked whether test prompts still produced the requested subjects.

Schedule · ~1600 steps, saved every epoch

Batch 2, cosine decay, roughly 10 epochs over 40 images. I saved a checkpoint per epoch and chose between them by generating the same held-out subjects with each, not by looking at the loss curve. Loss going down and the LoRA being usable are different things.

No regularisation images

I did not use prior-preservation images for this style experiment. I evaluated the results by comparing the same held-out subjects across checkpoints.

Evaluating and revising the LoRA

I used recurring problems in the test images to decide which training settings to revisit:

Overfitting · new subjects inherit old shapes

Some test souvenirs resembled objects from the training images. I treated this as a possible sign of overfitting and revisited the rank, training duration and variety of references.

Underfitting · style drifts between runs

When outlines or colours varied too much across the set, I compared training duration and rank alongside the reference conditioning. I judged changes against the same test prompts.

Weight · swept, not guessed

I generated the same three subjects at 0.4 / 0.6 / 0.8 / 1.0 and read them as a set. Below about 0.6 the palette drifted; at 1.0 the model started ignoring the subject and reproducing composition from the dataset. 0.78 was where style held and prompts were still obeyed.

Composition · let each tool hold one thing

I combined the LoRA with IP-Adapter and ControlNet: the LoRA guided the rendering style, the reference image supported the palette, and ControlNet guided framing. I tuned their strengths together and checked the collection for consistency.

Checkpoint coupling

I kept the base checkpoint fixed because the LoRA was trained and evaluated against that model. Changing it would require testing the style and prompt response again.

I evaluated changes with a fixed set of subjects outside the training data, then checked whether the resulting souvenirs matched the rest of the collection.

Batch generation settings

Once the graph was stable, I changed the subject tokens while keeping the model, LoRA weight, reference image and sampling settings fixed for the batch.

  1. Explore: generate candidates for several landmarks off the base checkpoint and measure how far apart they drift on line weight, palette and rendering.
  2. Train: curate ~40 reference frames of the target look, caption only their contents, and train a low-rank style LoRA; pick the epoch by testing it on subjects that were not in the training set.
  3. Pin the graph: freeze checkpoint, LoRA weight, IP-Adapter reference, ControlNet preprocessor and sampler settings into one saved ComfyUI workflow.
  4. Batch: drive that workflow through the ComfyUI API from a list of places, swapping only the subject tokens, so a city’s whole souvenir set comes out in one run.
  5. Post: background removal to transparent PNG, upscale, then drop into the Figma UI and judge the set together, not one image at a time.

I reviewed the souvenirs together in the virtual room. Differences in line weight, colour and shading were easier to spot across a collection than in individual images.

05Challenges & solutions

Challenge

AI assets didn’t match each other

Each generation came back with different line weights, palettes and rendering styles, so twelve souvenirs on one shelf didn’t read as one game.

Solution

Saved generation workflow

A style LoRA plus a fixed IP-Adapter reference, ControlNet framing and sampler settings, saved as one ComfyUI workflow. Only the subject tokens vary, to reduce variation between generations.

Challenge

Is it a game, a tool or a social app?

The SWOT flagged an unclear genre fit and strong competitors: cozy games, travel planners and AI chatbots.

Solution

Collection and travel features

The prototype pairs a home-decoration and collection loop with travel-planning and community features.

Challenge

Safety and privacy concerns

Interviewees ranked safety first, but location and home visits raise privacy risks.

Solution

Feedback-driven safety features

Added real-time safety alerts, misconduct reporting, an emergency button, close-friend tiers and visit blocking after prototype testing.
